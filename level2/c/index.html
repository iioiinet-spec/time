자주 하는 실수
“정확히 하나”와 “적어도 하나”를 헷갈리는 경우입니다. 정확히 하나는 교집합을 두 번 빼야 합니다(한 번은 중복 제거, 한 번은 아예 제외).

2. 세 집합의 포함배제

정리
|A ∪ B ∪ C| = |A| + |B| + |C| − |A∩B| − |B∩C| − |C∩A| + |A∩B∩C|

그림의 숫자는 |A| + |B| + |C|를 할 때 그 조각이 몇 번 세어지는지를 나타냅니다.

조각더할 때 세어진 횟수두 집합 교집합을 뺀 뒤세 교집합을 더한 뒤
한 집합에만1번1번1번
두 집합에만2번2 − 1 = 1번1번
세 집합 모두3번3 − 3 = 0번0 + 1 = 1번

가운데 조각은 세 번 더했다가 세 번 빼서 0번이 되어 버립니다. 그래서 한 번 다시 더해 주어야 정확히 한 번 세어집니다.

기억하는 법
더하고 → 빼고 → 더하고가 번갈아 나옵니다. 집합이 네 개면 마지막에 네 집합의 교집합을 빼게 됩니다.

정리
전체가 U일 때
(어느 것도 아닌 것의 개수) = |U| − |A ∪ B ∪ C|

같은 일을 하는 두 프로그램
C
#include <stdio.h>

int main(void) {
    int N = 1000;
    /* 전수 조사 */
    int cnt = 0;
    for (int n = 1; n <= N; n++)
        if (n % 2 && n % 3 && n % 5) cnt++;
    /* 포함배제 식 */
    int u = N/2 + N/3 + N/5 - N/6 - N/10 - N/15 + N/30;
    printf("전수 조사: %d\n", cnt);
    printf("포함배제: %d - %d = %d\n", N, u, N - u);
    printf("각 항: %d %d %d | %d %d %d | %d\n",
           N/2, N/3, N/5, N/6, N/10, N/15, N/30);
    return 0;
}

13명이 모이면 생일이 같은 달인 두 사람이 반드시 있습니다. 왜 그럴까요?

달은 12개뿐인데 사람이 13명이므로, 한 사람씩 서로 다른 달에 배정하려 해도 12명에서 달이 동납니다. 13번째 사람은 이미 누군가 있는 달에 들어갈 수밖에 없습니다.

물건 4개를 상자 3개에 넣으면 아무리 고르게 넣어도 어느 한 상자에는 2개 이상이 들어갑니다.

이 단순한 사실이 “반드시 있다”를 증명하는 강력한 도구가 됩니다. 어려운 점은 원리 자체가 아니라 무엇을 상자로 삼을지 정하는 일입니다.

②개념과 정리

1. 기본형과 일반형

기본형
물건 n + 1개를 상자 n개에 넣으면, 적어도 한 상자에는 2개 이상이 들어간다.
일반형
물건 N개를 상자 k개에 넣으면, 적어도 한 상자에는 ⌈N ÷ k⌉개 이상이 들어간다. (⌈x⌉는 x 이상인 가장 작은 정수)

4. 연속한 수의 합이 n의 배수가 되는 구간

정리
정수 a₁, a₂, …, aₙ이 있으면, 연속한 몇 개의 합이 n의 배수가 되는 구간이 반드시 있다.

부분합 S₀ = 0, S₁ = a₁, S₂ = a₁ + a₂, …, Sₙ = a₁ + … + aₙ의 n + 1개를 생각합니다. 이들을 n으로 나눈 나머지는 0부터 n − 1까지 n가지뿐입니다.

n + 1개를 n개 상자에 넣었으므로 나머지가 같은 두 부분합 Sᵢ, Sⱼ (i < j)가 있습니다. 그러면

Sⱼ − Sᵢ = ai+1 + … + aⱼ 가 n의 배수입니다.

예 (n = 5)a31415
부분합 S0348914
5로 나눈 나머지034344

나머지가 3인 것이 S₁과 S₃이므로 S₃ − S₁ = 1 + 4 = 5가 5의 배수입니다. 나머지가 4인 S₂와 S₄에서도 S₄ − S₂ = 1 + 5 … 실제로는 S₄ − S₂ = 9 − 4 = 5로 역시 5의 배수입니다.

핵심 아이디어
부분합의 나머지를 상자로 삼는 것이 이 유형의 표준 풀이입니다. S₀ = 0을 넣어야 물건이 n + 1개가 된다는 점이 중요합니다.

예제 1 · 대표 문제
1부터 20까지의 수 중 몇 개를 고르면 반드시 한 수가 다른 수의 약수인 두 수가 포함되는가? 가장 작은 개수를 구하시오.
풀이

① 상자 설계. 모든 자연수는 2ᵏ × (홀수) 꼴로 유일하게 쓸 수 있다. 홀수 부분이 같은 두 수는 한쪽이 다른 쪽의 2배, 4배, …이므로 약수 관계다.

홀수 부분135791113151719
그 상자의 수들1,2,4,8,163,6,125,10,207,149,181113151719

1부터 20까지의 수는 홀수 부분이 1, 3, 5, …, 19인 10개의 상자에 나뉘어 들어간다.

② 11개면 반드시. 11개를 고르면 상자가 10개뿐이므로 비둘기집에 의해 같은 상자에서 두 개를 고르게 된다. 같은 상자의 두 수는 약수 관계다.

③ 10개로는 피할 수 있다. 11, 12, 13, …, 20의 10개를 고르면 어떤 두 수도 약수 관계가 아니다. 작은 수의 2배가 22 이상이 되어 범위를 벗어나기 때문이다.

①~③에 따라 답은 11개다.

검산
11~20에서 실제로 확인해 보면 12와 24, 10과 20 같은 쌍이 없습니다. 어떤 두 수를 골라도 큰 쪽이 작은 쪽의 배수가 아닙니다.
예제 2 · 나머지 상자
임의의 정수 6개를 고르면, 그중 차가 5의 배수인 두 수가 반드시 있음을 보이시오.
풀이

① 상자 설계. 목표가 “차가 5의 배수”이므로 5로 나눈 나머지를 상자로 삼는다. 나머지는 0, 1, 2, 3, 4의 5가지다.

② 비둘기집. 정수 6개를 5개 상자에 넣으므로, 적어도 한 상자에 2개 이상이 들어간다.

③ 결론. 같은 상자에 든 두 수 a, b는 5로 나눈 나머지가 같으므로 a − b가 5의 배수다.

5개로는 왜 안 되는가 1, 2, 3, 4, 5를 고르면 나머지가 각각 1, 2, 3, 4, 0으로 모두 달라 차가 5의 배수인 쌍이 없다. 따라서 6개가 최소다.

핵심

#include <stdio.h>

int a[20], found = 0;
char buf[64];

int ok(int c) {                  /* 약수 관계가 없으면 1 */
    for (int i = 0; i < c; i++)
        for (int j = i + 1; j < c; j++)
            if (a[j] % a[i] == 0) return 0;
    return 1;
}

void rec(int s, int c, int need, int *cnt) {
    if (c == need) {
        if (!ok(c)) return;
        (*cnt)++;
        if (need == 10 && !found) {  /* 반례 하나 저장 */
            found = 1;
            int p = 0;
            for (int i = 0; i < c; i++)
                p += sprintf(buf + p, i ? " %d" : "%d", a[i]);
        }
        return;
    }
    for (int v = s; v <= 20; v++) { a[c] = v; rec(v + 1, c + 1, need, cnt); }
}

from itertools import combinations

def ok(c):                              # 약수 관계가 없으면 True
    return not any(b % a == 0
                   for a, b in combinations(c, 2))

for need in (10, 11):
    good = [c for c in combinations(range(1, 21), need) if ok(c)]
    print(f"{need}개 중 약수 관계 없는 경우: {len(good)}가지")
    if need == 10:
        print("10개 반례: " + " ".join(map(str, good[0])))

long C(int n, int r) {                 /* 조합 */
    long v = 1;
    if (r > n - r) r = n - r;
    for (int i = 1; i <= r; i++) v = v * (n - r + i) / i;
    return v;
}

int main(void) {
    int n = 10, cnt1 = 0, cnt0 = 0;
    for (int x = 0; x <= n; x++)
        for (int y = 0; y <= n; y++) {
            int z = n - x - y;
            if (z < 0) continue;
            cnt0++;                     /* 음이 아닌 해 */
            if (x >= 1 && y >= 1 && z >= 1) cnt1++;
        }

    int total = 1 << 5, ge2 = 0, le1 = 0;
    for (int m = 0; m < total; m++) {
        int heads = 0;
        for (int i = 0; i < 5; i++) heads += (m >> i) & 1;
        if (heads >= 2) ge2++; else le1++;

    show("같은 켤레", same, cnt);
    return 0;
}

확률을 (해당 경우) ÷ (전체 경우)로 계산하려면 전체 경우들이 모두 같은 가능성을 가져야 한다. 두 동전을 구별할 때와 하지 않을 때를 비교한다.

① 구별했을 때 동전을 A, B로 구별하면 결과는 (앞, 앞), (앞, 뒤), (뒤, 앞), (뒤, 뒤)의 4가지다. 각 동전은 앞뒤가 반반이고 서로 영향을 주지 않으므로 네 경우는 모두 같은 가능성이다. 따라서

P(앞앞) = 1⁄4

② 구별하지 않았을 때 “앞앞, 앞뒤, 뒤뒤”의 3가지로 보면, 이 중 앞뒤는 (앞, 뒤)와 (뒤, 앞) 두 가지가 합쳐진 것이다.

③ 무엇이 어긋나는가 같은 가능성이 아닌 것을 표본공간으로 삼으면 확률의 기본 식이 성립하지 않는다. 실제로 동전을 여러 번 던져 보면 앞뒤가 섞여 나오는 비율이 약 1⁄2로, 1⁄3과 크게 다르다.
