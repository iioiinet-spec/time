1왜 필요한가

12장의 이분 탐색은 배열의 첨자를 좁혔다. 이 장은 배열 없이 “답 그 자체”를 좁힌다. 다섯 줄은 그대로인데 쓰는 자리가 완전히 달라진다.

1.1 답을 모르면 물어볼 수 없다 — 정말 그런가

랜선 자르기

길이가 제각각인 랜선 N개가 있다. 이것을 같은 길이로 잘라 K개 이상을 만들려 한다. 가능한 가장 긴 길이는? (남는 조각은 버린다)

“가장 긴 길이”를 바로 구하는 공식은 없다. 그런데 질문을 바꾸면 쉬워진다.

원래 질문 — 어렵다

“가장 긴 길이는 얼마인가?”
→ 어디서부터 시작할지 모른다

바꾼 질문 — 쉽다

“길이 x로 자르면 K개가 나오는가?”
→ 한 번 훑으면 바로 안다

바꾼 질문은 예/아니오로 답하는 판정 문제다. 그리고 결정적으로, 이 답은 x가 커질수록 한 방향으로만 바뀐다.

랜선 802 743 457 539,  K = 11

   x :    1   50  100  150  200  201  250  300  400
개수 : 2541   49   24   15   11   10    8    6    5
  ok :    참   참   참   참   참  거짓  거짓  거짓  거짓
                               ↑ 마지막 '참' 이 답

참이 쭉 이어지다 한 번 거짓으로 바뀌고 다시는 참이 되지 않는다. 그렇다면 12장의 이분 탐색을 그대로 쓸 수 있다 — 배열 대신 “x의 범위”를 좁히면 된다.

1.2 왜 이렇게까지 하는가

$ ./lan      x 를 1부터 하나씩 올려 보는 방법과 비교

예시에서 ok 호출 16번 — 범위에 따라 달라진다

판정 함수 ok(x)는 랜선을 전부 훑으므로 한 번에 O(N)이다. 선형 탐색은 그것을 2만 번 넘게 부르고, 이분 탐색은 예시에서 16번 부른다. 범위가 10억이어도 30번이면 끝난다(4.1절) — 12장에서 외운 “log₂(10억) ≈ 30”이 여기서 값을 한다.

2개념

2.1 세 단계로 생각한다

단계할 일랜선 자르기에서는
①답을 x로 놓는다
그리고 x의 범위를 정한다		x = 자를 길이. 범위는 1 ≤ x ≤ max(len)
②판정 함수 ok(x)를 만든다
예/아니오로 답하는 함수		ok(x) = (Σ len[i]/x ≥ K)
③단조성을 확인한다
참/거짓이 한 번만 바뀌는가		x가 커지면 조각 수가 줄어든다 → T…TF…F

③을 건너뛰면 안 된다

②까지만 하고 바로 이분 탐색을 돌리는 학생이 많다. 단조가 아니면 이분 탐색이 내놓는 값은 아무 의미가 없다(4.3절에서 측정). “왜 단조인가”를 한 문장으로 말할 수 없으면 아직 ②가 틀린 것이다.

2.2 두 가지 모양, 두 가지 틀

둘은 사실 같은 코드다

모양 B에서 “마지막 참”의 바로 다음이 “처음 거짓”이다. 그러니 “처음 거짓”을 찾아 1을 빼면 된다. 그리고 “처음 거짓”을 찾는 것은 12장 lower_bound와 글자 하나 다르지 않다 — 비교하는 대상이 a[mid] < key에서 ok(mid)로 바뀌었을 뿐이다.

3구현

3.1 두 가지 틀 — 필수 구현

/* ok(x)는 각 문제의 판정 함수. [lo, hi]는 닫힌 구간. */
static int ok(long long x);  /* 뒤에서 정의 */
/* 모양 B: T...TF...F에서 마지막 참. 없으면 lo-1 */
static long long last_true(long long lo, long long hi) {
    long long L = lo, H = hi + 1;
    while (L < H) {
        long long mid = L + (H - L) / 2;
        if (ok(mid)) L = mid + 1;
        else         H = mid;
    }
    return L - 1;
}
/* 모양 A: F...FT...T에서 처음 참. 없으면 hi+1 */
static long long first_true(long long lo, long long hi) {
    long long L = lo, H = hi + 1;
    while (L < H) {
        long long mid = L + (H - L) / 2;
        if (!ok(mid)) L = mid + 1;
        else          H = mid;
    }
    return L;
}

세 가지를 확인한다

  • hi + 1로 시작한다. 답의 범위가 [lo, hi](닫힌)인데 반열린 틀을 쓰기 때문이다. hi가 INT_MAX여도 long long으로 안전하다(단, lo > LLONG_MIN이고 hi < LLONG_MAX)
  • last_true만 − 1이 붙는다. “처음 거짓”을 찾았으니 그 앞이 답이다 — 이 −1을 빠뜨리는 것이 이 장 최대의 실수(4.3절)
  • “없음”도 자연스럽게 나온다. last_true는 전부 거짓일 때 lo−1, 전부 참일 때 hi. first_true는 전부 참일 때 lo, 전부 거짓일 때 hi+1이 나온다

3.2 랜선 자르기

※ 아래는 3.1절과 이어서 보는 핵심 코드 조각입니다. 입력·main 함수까지 포함한 독립 실행 가능한 C11 코드는 부록 파일에 제공합니다.

/* 3.1절의 last_true()와 연결해 사용 */
#define MAXN 1000000
static int len[MAXN], N;
static long long K;

static int ok(long long x) {
    long long s = 0;
    for (int i = 0; i < N; i++) {
        s += len[i] / x;     /* x >= 1 */
        if (s >= K) return 1;  /* 조기 종료 */
    }
    return 0;
}
/* N, K, len[] 입력 이후 */
int mx = 0;
for (int i = 0; i < N; i++)
    if (len[i] > mx) mx = len[i];
printf("%lld\n", last_true(1, mx));

  검산 : x=200 -> 11개,  x=201 -> 10개

lo = 1이지 0이 아니다

x = 0이면 len[i] / 0이 되어 C에서 정의되지 않은 동작이 발생한다(비정상 종료할 수 있음). 판정 함수가 의미를 갖는 범위를 먼저 정하는 것이 ①단계다. 범위를 잘못 잡으면 틀이 아무리 맞아도 소용없다.

3.3 전수 검증 — 12장 검사기를 고쳐 쓴다

12장 도전 C2 (5)에서 예고한 것을 실행한다. 바꿀 것은 “무엇을 생성하는가”뿐이다.

항목12장 (배열 탐색)13장 (값 탐색)
생성할 것모든 비내림 수열한 번만 뒤집히는 모든 참/거짓 패턴
개수길이 1~6·값 5종 → 461가지 비내림 수열길이 L → 정확히 L+1가지

나머지전수 생성 → 느린 답과 대조 → 반복 상한 — 그대로

for (int k = 0; k <= L; k++) {             /* 앞 k개가 참인 패턴 */

패턴이 L+1가지뿐이라 전수 검증이 거의 공짜다

배열 탐색은 수열의 가짓수가 폭발하지만, 단조 패턴은 “어디서 뒤집히는가” 하나로 결정되므로 길이 L이면 딱 L+1가지다. L = 1000이면 한 방향당 1001패턴이다. 다만 이 전수 검사는 추상적인 단조 패턴에서 탐색 틀만 검증한다. 실제 문제의 판정 함수가 옳고 단조인지까지 증명해 주지는 못한다.

변종 (4)가 13가지 전부 틀렸다

− 1을 빠뜨리면 언제나 1만큼 큰 값이 나온다. 하나도 안 맞으니 예제 하나만 돌려 봐도 바로 걸린다 — 오히려 다행인 버그다. 무서운 것은 변종 (3)처럼 13가지 중 5가지만 틀리는 쪽이다.

4복잡도와 함정

4.1 복잡도 — ok 호출 횟수로 센다

매개 변수 탐색의 비용은 “ok를 몇 번 부르는가 × ok 한 번의 비용”이다.

         범위 길이 L      ok 호출     ceil(log₂(L+1))
                  15            4               4
                 1000        9~10               10
              1000000       19~20               20
           1000000000      29~30              30
문제ok 한 번호출 횟수전체
랜선 자르기O(N)약 30O(N log(범위))
공유기 설치 (도전 C1)O(N)약 30정렬 포함 O(N log N + N log D), D=좌표 범위
x를 1씩 올리기O(N)최대 10억사실상 불가능

“범위가 커도 괜찮다”가 이 기법의 전부다

답의 범위가 100만이든 10억이든 호출 횟수는 20에서 30으로 늘 뿐이다. 그래서 매개 변수 탐색은 답의 범위를 넉넉하게 잡아도 손해가 거의 없다. 범위를 아슬아슬하게 잡으려다 틀리는 것이 훨씬 비싸다.

4.2 함정 ① — 넘침이 두 군데서 난다

(가) mid 계산

lo = 2000000000, hi = 2100000000
  (lo + hi) / 2        = 정의되지 않은 동작(int 넘침)
  lo + (hi - lo) / 2 = 2050000000

12장에서는 배열 첨자라 생길 일이 없었다. 여기서는 바로 생긴다 — 답의 범위가 10억대인 문제가 흔하기 때문이다.

(나) 판정 함수 안의 합계

랜선 10,000개, 각 길이 2,147,483,647, x = 1
  long long 합계 = 21,474,836,470,000
  int       합계 = 정의되지 않은 동작(정답 보장 없음)

(나)가 더 찾기 어렵다

(가)는 잘못된 mid가 나올 수 있고, (나)는 판정 결과가 달라질 수 있다. 둘 다 부호 있는 정수 넘침이므로 C 표준상 결과가 보장되지 않는다. 오답·비정상 종료 등 증상은 실행 환경에 따라 달라진다.
판정 함수를 쓸 때마다 “여기서 더해지는 값의 최댓값은?”을 먼저 적는다. 11장 연습 04(넓이 넘침), 12장 C1 (4)와 같은 습관이다.

4.3 함정 ② — 단조가 아니면 답이 없다

ok(x) = (x % 3 ≠ 0)처럼 참/거짓이 번갈아 나오는 함수에 이분 탐색을 돌려 보았다.

ok(x) = (x % 3 != 0),  범위 [1, 30]
  이분 탐색이 내놓은 답       : 23
  '참인 가장 큰 x' 의 실제 값 : 29

틀린 값을 아무 말 없이 돌려준다

오류도 경고도 없다. 23은 참이기는 하다 — 그래서 더 그럴듯해 보인다. 이분 탐색은 “단조”라는 약속 위에서만 의미가 있고, 그 약속을 스스로 확인해 주지 않는다.
그래서 ③단계(단조성 확인)가 필수다. 그리고 작은 범위에서는 자동으로 검사할 수 있다 — 도전 C2에서 만든다.

4.4 실수 이분 탐색 — 반복 상한과 정체 검사

답이 실수일 때 while (hi - lo > eps)만 사용하면 표현 가능한 두 실수 사이에 더 이상 중간값이 없어서 끝나지 않을 수 있다. 고정 반복 수와 mid==lo || mid==hi 검사를 조합하면 안전하다.

double 의 '옆 수와의 간격'(ulp)
          1e+00 : 2.220e-16      1e+12 : 1.221e-04
          1e+06 : 1.164e-10      1e+15 : 1.250e-01

x·x = T 를 while (hi - lo > 1e-9) 로 푼다
             T          답(√T)      반복   결과
         2e+00    1.414214e+00        31   정상 종료
         1e+12    1.000000e+06        70   정상 종료
         1e+24    1.000000e+12       501   <-- 끝나지 않는다
         1e+30    1.000000e+15       501   <-- 끝나지 않는다

왜 끝나지 않는가

답이 10¹² 근처면 그 동네 double의 옆 수와의 간격이 이미 1.2×10⁻⁴다. hi − lo를 아무리 줄여도 10⁻⁹보다 작아질 수가 없다. 중간값이 경계값과 같아지면 값이 갱신되지 않는데도 폭이 10⁻⁹보다 큰 상태가 남을 수 있다.

해법 — 반복 횟수를 고정한다

고정 횟수 탐색의 검증 예
    T = 2       → 약 1.41421356237
    T = 1e12    → 약 1,000,000
    T = 1e24    → 약 1,000,000,000,000
    T = 1e30    → 약 1,000,000,000,000,000
  ※ 초기 구간과 반올림에 따라 실제 상대오차는 달라진다.

정확한 산술에서는 100회 후 구간 폭이 초기 폭의 약 2⁻¹⁰⁰배가 된다. 하지만 부동소수점 반올림으로 그 전에 정체할 수 있으며, 임의의 초기 구간에서 100회가 항상 충분한 것은 아니다. 참값을 처음부터 포함하는 구간을 잡고 정체 여부를 검사한다.

/* T > 0, sqrt(T) 근사. math.h 포함 */
double lo = 0.0, hi = 1.0;
while (hi < T / hi) hi *= 2.0; /* 답을 포함하도록 확대 */
for (int i = 0; i < 100; i++) {
    double mid = lo + (hi - lo) / 2;
    if (mid == lo || mid == hi) break;
    if (mid <= T / mid) lo = mid;
    else hi = mid;
}
Q. 100회면 너무 많지 않나요?
아니다. 필요한 반복 수는 초기 구간 크기와 요구 오차에 달려 있다. 100회는 자주 쓰이는 실무적 상한 예시이며, 반복이 정체하면 조기에 멈추도록 해야 한다. ok가 O(N)이고 N = 100만이어도 100회면 1억 회 판정 내부 반복이므로 실행 시간은 컴퓨터·입력·컴파일러에 따라 다르다. 안전을 아주 싸게 사는 셈이다.
