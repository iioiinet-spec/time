1왜 필요한가

11장에서 정렬을 손에 넣었다. 이 장은 정렬되어 있다는 사실을 무기로 쓰는 첫 기법이다. 그리고 설계서가 적었듯 “이분 탐색의 경계 처리는 이후 전 단원의 전제”가 된다.

1.1 질의가 많으면 선형 탐색은 무너진다

정렬된 배열에서 “이 값이 어디 있는가”를 Q번 묻는다고 하자. 찾는 위치가 고르게 분포한다면 선형 탐색은 성공 질의당 평균 약 N/2개를 검사한다. 존재하지 않는 값을 찾을 때는 N개를 모두 볼 수도 있다.

n = 100만에서 비교 횟수의 비는 10,007,499,563 ÷ 399,029 ≈ 25,079배다. 이론값은 (n/2) ÷ log₂n = 500,000 ÷ 20 = 25,000 — 거의 그대로다.
그런데 표에 표시된 실행 시간의 비는 약 1,206배로 훨씬 작다. 선형 탐색은 메모리를 순서대로 읽어 한 걸음이 매우 싸고, 이분 탐색은 멀리 건너뛰므로 한 걸음이 비싸기 때문이다 — 10장 3.4절에서 본 것과 같은 현상이다. 실측값은 컴퓨터, 컴파일 옵션, 데이터와 측정 방식에 따라 달라진다.

1.2 이 장이 어려운 이유

이분 탐색의 코드는 다섯 줄이다. 그런데 PART 2에서 가장 많이 틀린다. 이유는 하나다 — 조금씩 다른 변종이 너무 많고, 틀린 변종도 대부분의 입력에서는 맞는 답을 낸다.

그래서 이 장은 변종들을 전부 돌려 보는 것으로 시작한다. 길이 1~6, 값 0~4인 모든 비내림 수열과 모든 질의값, 질의값 0~5를 포함해 총 2,766가지를 하나도 빠뜨리지 않고 검사했다. (연습 07은 질의값을 −1~5로 늘려 3,227가지를 검사한다.)

  • (2)는 조용히 틀린다. 2,766 중 639번 — 4번에 3번은 맞는 답을 낸다. 그래서 테스트를 통과해 버린다
  • (3)은 일부 입력에서 멈추지 않는다. (4)는 멈추지 않거나 배열 밖을 읽을 수도 있다. C에서는 경고 없이 오동작할 수 있다
  • (6)은 틀린 게 아니다. 2.4절에서 밝힌다 — 그것은 다른 함수다

2개념

2.1 반열린 구간 [lo, hi) — 이 교재의 표준

이분 탐색이 헷갈리는 가장 큰 원인은 “지금 보고 있는 범위가 어디까지인가”가 코드마다 다르기 때문이다. 이 교재는 하나로 고정한다.

약속

다음에 비교할 배열 원소의 인덱스 범위는 [lo, hi)이다. hi는 후보에 포함되지 않는다.
처음에는 lo = 0, hi = n이다. 배열 원소는 0~n−1번을 검사하지만, 정답인 경계 위치는 lo ≤ 답 ≤ hi를 만족한다. n도 유효한 반환값으로, 모든 원소가 key보다 작아 배열 끝에 삽입해야 하는 경우다.

반열린 구간을 쓰면 좋은 세 가지

  • 남은 개수가 hi − lo다. 빈 구간은 lo == hi — hi = lo-1 같은 이상한 상태가 없다
  • 끝났을 때 lo가 곧 답이다. 따로 기억해 둘 변수가 없다
  • 모든 원소가 key보다 작으면 결과가 n으로 나온다. 단, 그 밖의 위치도 key가 실제로 존재하지 않을 수 있으므로 존재 여부는 추가로 검사한다

2.2 다섯 줄과 그 뜻

int lo = 0, hi = n;                 /* 비교할 원소의 범위는 [0, n) */
while (lo < hi) {                   /* 후보가 남아 있는 동안 */
    int mid = lo + (hi - lo) / 2;   /* 가운데 (lo 이상 hi 미만) */
    if (a[mid] < key) lo = mid + 1; /* 경계 답은 mid보다 오른쪽 */
    else              hi = mid;     /* 경계 답은 mid 이하 (hi=mid) */
}
/* 여기서 lo == hi 이고, 그 값이 답 */

두 줄의 비대칭이 핵심이다

lo = mid + 1에는 +1이 있고 hi = mid에는 없다. 이상해 보이지만 당연하다 —
a[mid] < key이면 mid는 확실히 답이 아니므로 버린다(그래서 +1).
아니면 mid는 답일 수도 있으므로 후보에 남긴다. 다만 hi = mid로 바꾸면 mid 원소는 더 이상 [lo, hi)에서 검사하지 않는다. 대신 가능한 정답 경계가 mid일 수 있다는 사실을 보존한다. 항상 lo ≤ 정답 ≤ hi가 유지된다.

2.3 왜 멈추는가 — 무한 루프의 정체

1.2절에서 변종 (3)은 1,980건에서 반복 상한을 초과했다. 변종 (4)는 같은 1,980건에서 반복이 진행되지 않았으며, 나머지 786건에서는 배열 밖 접근이 발생할 수 있다. 왜 그런지 알면 이분 탐색을 반쯤 이해한 것이다.

멈추려면 한 가지만 지키면 된다

반복할 때마다 hi − lo가 반드시 줄어들어야 한다.

상황mid표준 (1)변종 (3) lo = mid
lo=3, hi=4
(후보 1개)		3lo=4 또는 hi=3 → 구간이 빈다lo=3 → 아무것도 안 바뀐다
lo=3, hi=5
(후보 2개)		4lo=5 또는 hi=4 → 1개로lo=4 → 1개로 (여기선 괜찮다)

mid = lo + (hi-lo)/2는 버림이므로 후보가 1개뿐일 때 mid == lo가 된다. 이때 lo = mid는 전진이 없다 — 영원히 같은 자리를 맴돈다.

변종 (4) while (lo <= hi)는 배열 밖 접근도 가능

lo == hi < n이면 그 안에서 hi = mid가 그대로여서 반복이 멈출 수 있다. lo == hi == n이면 a[n]을 읽으므로 범위 밖 접근이 된다. 닫힌 구간 스타일을 쓰려면 반드시 hi = mid - 1이어야 하고(변종 5), 그러면 답을 따로 기억할 변수가 필요해진다. 섞어 쓰면 반드시 사고가 난다.

2.4 upper_bound — 부등호 하나 차이

변종 (6) a[mid] <= key는 틀린 코드가 아니었다. 전수 검증으로 확인했다.

$ ./main
'a[mid] <= key' 버전이 upper_bound 와 다른 경우 : 0   (2,766가지 전수)
함수조건돌려주는 자리
lower_bounda[mid] < keykey 이상이 처음 나오는 자리 — key가 들어갈 가장 왼쪽
upper_bounda[mid] <= keykey 초과가 처음 나오는 자리 — key가 들어갈 가장 오른쪽

그래서 개수 세기가 공짜로 따라온다

key인 원소들은 lower_bound부터 upper_bound 직전까지 연속해 모여 있다(정렬되어 있으므로). 따라서
key의 개수 = upper_bound(key) − lower_bound(key)
세는 코드를 따로 짤 필요가 없다. 두 함수의 차이가 부등호 하나뿐이라는 사실이 여기서 값을 한다.

3구현

3.1 필수 구현 세 가지

/* key 이상이 처음 나오는 자리. 없으면 n */
static int lower_bound(const int *a, int n, int key){
    int lo = 0, hi = n;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] < key) lo = mid + 1; else hi = mid;
    }
    return lo;
}
/* key 초과가 처음 나오는 자리. 부등호에 '=' 하나만 더 붙는다 */
static int upper_bound(const int *a, int n, int key){
    int lo = 0, hi = n;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] <= key) lo = mid + 1; else hi = mid;
    }
    return lo;
}
/* 개수 세기 (정렬된 배열만) */
static int count_key(const int *a, int n, int key){
    return upper_bound(a, n, key) - lower_bound(a, n, key);
}
/* '있는가' 판정 — 함수로 만들면 바로 재사용 가능 */
int contains_key(const int *a, int n, int key){
    int p = lower_bound(a, n, key);
    return p < n && a[p] == key;      /* 단락 평가로 a[n] 접근 방지 */
}

p < n을 먼저 쓰는 이유

key가 모든 원소보다 크면 p == n이 된다. a[p]를 먼저 읽으면 배열 밖 접근이다. C의 &&는 왼쪽이 거짓이면 오른쪽을 아예 보지 않으므로, 순서만 지키면 안전하다. 순서를 바꾸면 C에서 정의되지 않은 동작이며, 실행 결과를 예측할 수 없다.

   key    lower_bound    upper_bound       개수
     0              0              0          0      모두보다 작다 -> 맨 앞
     3              1              4          3
     4              4              4          0      없는 값 -> 둘이 같다
     7              5              7          2
     9              7              9          2

표에서 읽어야 할 세 가지

  • 없는 값은 두 함수가 같은 값을 돌려준다(key=4에서 둘 다 4). 그래서 개수가 0이 된다 — “없음”을 따로 처리하지 않아도 된다
  • key=4의 답 4는 “4를 끼워 넣을 자리”다. 그 자리에 넣으면 정렬이 유지된다
  • 모두보다 크면 n이 나온다. 배열 밖 자리이고, 그래서 p < n 검사가 필요하다

3.3 전수 검증 — 이 장에서 반드시 익힐 습관

이분 탐색은 경계 조건을 잘못 써도 일부 작은 입력에서는 맞는 답이 나올 수 있다. 변종 (2)는 2,766가지 중 2,127가지에서 정답을 냈다. 무작위 테스트만으로 충분하다고 보장할 수 없다. 그래서 이 장에서는 작은 입력을 전부 만들어 검사한다.

/* 길이 1~6, 값 0~4 인 '모든 비내림 수열'을 만들어 검사한다 */
static int b[8], bn, errors, cases;

static int truth(int key){                 /* 믿을 수 있는 느린 답 */
    int i = 0; while (i < bn && b[i] < key) i++; return i;
}
static void rec(int pos, int maxlen, int minv){
    if (pos > 0) {
        bn = pos;
        for (int key = 0; key <= 5; key++) {
            cases++;
            if (lower_bound(b, bn, key) != truth(key)) errors++;
        }
    }
    if (pos == maxlen) return;
    for (int v = minv; v <= 4; v++) { b[pos] = v; rec(pos+1, maxlen, v); }
}

/* main에서 호출할 때: */
/* rec(0, 6, 0); printf("%d cases, %d errors\n", cases, errors); */

두 가지 장치

  • minv를 넘겨 비내림만 만든다. 정렬되지 않은 입력은 이분 탐색의 전제를 벗어나므로 검사 대상이 아니다
  • 질의값을 0부터 5까지 — 값의 범위(0~4)보다 하나 넓게 잡는다. “모두보다 큰 값”이라는 경계를 반드시 포함시키기 위해서다

무한 루프를 검사기가 먼저 잡게 한다

틀린 변종은 멈추지 않을 수 있다. 그러면 검사기 자체가 죽어 아무것도 알아내지 못한다. 반복 횟수 상한을 두고, 넘으면 “무한 루프”로 보고하게 한다 — 1.2절의 표에서 1,980이라는 숫자가 그렇게 나온 것이다. 10장 연습 06의 check()에서 쓴 것과 같은 장치다.

Q. 길이 6, 값 0~4면 너무 작지 않나요?
대표적인 경계 오류를 찾기에는 유용하다. 많은 이분 탐색 오류가 경계에서 드러나기 때문이다 — 후보가 1개 또는 2개 남았을 때, 답이 맨 앞·맨 뒤일 때, 같은 값이 연달아 있을 때. 길이 6이면 그 모든 조합이 들어 있다. 작은 범위 전수 검사는 강력한 검증 수단이지만, 모든 가능한 입력에 대한 올바름의 수학적 증명을 대체하지는 못한다.

4함정과 복잡도

4.1 네 가지 함정

함정증상바로잡기
① 정렬하지 않았다답이 그냥 틀린다이분 탐색의 전제다. 4.2절에서 측정
② lo = mid무한 루프버리는 쪽에 +1 (2.3절)
③ hi = mid - 1반열린 구간에서 답을 건너뛴다남기는 쪽은 hi = mid
④ (lo+hi)/2큰 값에서 넘침lo + (hi-lo)/2

④ 는 언제 실제로 문제가 되는가

lo = 2000000000, hi = 2100000000
  lo + hi = 4100000000  (수학적 합, 32비트 int 범위 초과)
  (lo + hi) / 2        : C에서 정의되지 않은 동작
  lo + (hi - lo) / 2   = 2050000000
  INT_MAX = 2147483647

배열 첨자와 매개 변수 탐색 모두 넘침을 주의

일반적인 배열 크기에서는 잘 드러나지 않지만, 매우 큰 배열 첨자도 32비트 합이 넘칠 수 있다. 그런데 13장 매개 변수 탐색은 첨자가 아니라 “답의 값”을 이분 탐색한다. lo와 hi가 모두 10억대 후반이면 lo+hi가 범위를 넘을 수 있다. 두 경계의 차 hi-lo도 int 범위를 넘지 않는 조건에서는 lo + (hi-lo)/2가 안전하다. 전체 범위가 더 크면 long long을 사용한다.

4함정과 복잡도 (이어서)

4.3 복잡도 — 반복 횟수를 직접 센다

후보 구간의 길이는 매 반복마다 절반 이하가 된다. n에서 시작해 1보다 작아지기까지 걸리는 횟수가 log₂n이다. 실제로 세어 보았다.

           n      평균 반복     ceil(log₂(n+1))
        1000           9.98              10
      100000          16.69              17
     1000000          19.95              20

이론과 거의 정확히 맞는다. 09·10장에서 연산 횟수와 실제 시간이 어긋나는 경우를 여럿 보았는데, 이분 탐색의 반복 횟수는 예측이 그대로 맞는 드문 경우다.

항목복잡도비고
한 번의 이분 탐색O(log N)N = 100만이면 20번
정렬 + Q번 질의O(N log N + Q log N)정렬 비용을 잊지 않는다
선형 탐색 Q번O(NQ)N=Q=100만이면 5×10¹¹ — 불가능
개수 세기O(log N)이분 탐색 두 번

N을 외우는 대신 20을 외운다

log₂(100만) ≈ 20, log₂(10억) ≈ 30이다. 정렬된 배열의 탐색 범위가 백만이면 약 20번, 십억이면 약 30번의 비교로 경계를 찾는다. 그래서 이분 탐색은 “질의당 O(log N)이므로 많은 질의에도 상대적으로 유리하다”는 뜻이 되고, 12·13·14장과 24장 세그먼트 트리가 전부 이 사실 위에 선다.

Q. 평균 반복이 19.95로 20보다 살짝 작은 이유는?
배열 길이가 2의 거듭제곱이 아니면 분할되는 왼쪽·오른쪽 구간 크기가 달라 경로에 따라 반복 횟수가 한 번 정도 차이 나기 때문이다. 다만 lower_bound는 값을 찾아도 멈추지 않고 끝까지 구간을 좁힌다(가장 왼쪽을 찾아야 하므로). 따라서 값이 일찍 발견되어 종료되는 것이 아니라, ⌊log₂n⌋ 또는 그 부근 횟수만큼 후보 범위를 줄인다 — 최악과 평균이 사실상 같다.

예제 2 네 가지 질문, 한 가지 도구

7도전 문제

C1합이 S인 두 수
수열 A와 정수 S가 주어진다. 서로 다른 두 위치 i < j 로 A[i] + A[j] = S인 쌍의 개수를 구하라. 2 ≤ N ≤ 100,000, 원소와 S는 각각 −10억 ~ 10억.
예 : A = 1 2 3 4 5 5, S = 7 → 2+5(두 번), 3+4(한 번) = 3쌍
(1) 모든 쌍을 보는 풀이의 복잡도는? N = 100,000에서 어림하라.
(2) 정렬한 뒤 각 A[i]에 대해 S − A[i]를 이분 탐색하면 된다. 같은 원소를 두 번 세지 않으려면 어느 범위에서 찾아야 하는가?
(3) 값이 중복될 수 있다. 개수를 세려면 무엇을 써야 하는가? (힌트 — 2.4절)
(4) S − A[i]를 int로 계산하면 위험하다. 왜이며 어떻게 고치는가? 찾는 값이 int 범위를 벗어날 수도 있으므로 탐색 함수의 key 자료형도 점검하라. 또한 정답 쌍의 수가 최대 4,999,950,000개임을 이용해 정답 변수의 자료형을 정하라.
(5) 구현해서 (1)과 시간을 비교하라. 중복이 많은 입력으로 측정할 것.
C2경계값 자동 검사기

(2) 생성할 입력의 범위를 정하고 그 선택의 근거를 쓰라. 길이 6으로 어떤 대표적 경계 오류를 확인할 수 있으며, 왜 모든 버그를 잡는다는 보장은 없는가?
(3) 무한 루프를 어떻게 잡을 것인가? 반복 횟수를 세려면 검사 대상 함수에 무엇이 필요한가? 두 가지 방법을 제시하고 장단점을 비교하라.
(4) 틀린 변종 세 개를 넣어 검사기가 오답·반복 상한 초과·범위 밖 접근을 구별하는지 보이라. 잡지 못하는 변종이 있다면 검사 범위를 넓혀라.
(5) 이 검사기를 13장 매개 변수 탐색에도 쓸 수 있는가? 쓸 수 없다면 무엇을 바꿔야 하는가?

8막히는 지점

흔한 생각무엇이 틀렸나바로잡기
“찾으면 바로 멈추면 되지”lower_bound는 가장 왼쪽을 찾아야 한다끝까지 구간을 좁힌다 (예제 1)
“lo = mid도 비슷하지”후보 1개일 때 전진이 없다 → 무한 루프 1,980번버리는 쪽에 +1 (2.3절)
“hi = mid-1이 안전해 보인다”답일 수도 있는 mid를 버린다 → 639번 틀림반열린 구간에서는 hi = mid
“테스트 통과했으니 맞다”이 검사의 변종 (2)는 약 77%에서 정답을 냈다전수 검증으로 확인한다 (3.3절)
“(lo+hi)/2면 충분”13장 값 탐색에서 넘친다지금부터 lo + (hi-lo)/2
“a[p]==key로 확인”p == n이면 배열 밖p < n && a[p]==key — 순서가 중요
“정렬은 당연히 했겠지”표본에 따라 일부 질의는 우연히 맞을 수 있다제출 전 정렬 여부를 눈으로 확인 (4.2절)
“개수 세는 함수를 따로”이미 있다 — ub − lb두 함수의 차이는 부등호 하나뿐 (2.4절)

자가 점검

  • 반열린 구간의 뜻과 장점 세 가지를 말할 수 있다
  • lower_bound를 보지 않고 다섯 줄로 쓸 수 있다
  • upper_bound와의 차이가 부등호 하나임을 안다
  • 개수 세기를 ub − lb로 구할 수 있다
  • 무한 루프가 생기는 자리를 정확히 지목할 수 있다
  • 전수 검증기를 만들어 자기 코드를 검사했다
  • p < n 검사를 먼저 쓰는 이유를 안다

다음은 13 매개 변수 탐색

이 장의 이분 탐색은 배열의 첨자를 좁혔다. 13장은 “답 그 자체”를 좁힌다.
“길이 x로 자를 수 있는가?”처럼 예/아니오로 답할 수 있고, x가 커질수록 한 방향으로만 바뀌는 질문을 만들면, 그 x를 이분 탐색할 수 있다. 배열이 없어도 된다.
그때도 경계 위치를 찾는 핵심 원리는 같지만, 검사할 조건과 경계의 자료형·종료 조건은 문제에 맞춰 설계해야 한다. 다만 hi가 10억대가 되므로 (lo+hi)/2에서 넘침이 발생할 수 있다(4.1절 ④). 그리고 C2에서 만든 검사기도 모양을 바꿔야 한다 — 그 준비가 C2 (5)다.
