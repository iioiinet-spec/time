1왜 필요한가

PART 2는 “정렬해 두면 무엇이 가능해지는가”를 묻는다. 이 장은 그 출발점으로, 정렬을 직접 짜지 않고 쓰는 법과 그때 반드시 지켜야 할 규약을 다룬다.

1.1 직접 짜지 않는다

정렬 알고리즘을 직접 구현하는 것은 공부로는 가치가 있지만, 대회에서는 거의 언제나 손해다. 짜는 시간도 들고 틀릴 여지도 크다.

$ ./bench      무작위 입력
        n      qsort(ms)   삽입 정렬(ms)       배수
    10000            1.0            16.5       17배
    20000            2.0            67.3       34배
    50000            5.4           416.5       77배

n이 5배 늘 때 삽입 정렬은 약 25배 느려졌다(16.5 → 416.5 ms). O(N²)에 가까운 증가다. 같은 환경·입력 패턴에서 N = 500,000이면 약 40초 이상으로 늘어날 수 있다(단순 외삽이며 보장값은 아니다).

1.2 진짜 이유 — 정렬은 수단이다

정렬 자체가 답인 문제는 드물다. 정렬해 두면 어려운 문제가 쉬워지기 때문에 정렬한다. 가장 단순한 예를 보자.

“이 수열에 같은 값이 두 번 나오는가?”

이중 루프로 모든 쌍을 보면 O(N²). 정렬하고 나면 같은 값은 반드시 이웃하므로 한 번 훑으며 옆자리만 비교하면 된다 — O(N log N).

중복이 없는 입력(최악)에서
        n   이중 루프(ms)   정렬 후 인접(ms)       배수
    20000           66.6              0.5      133배
    50000          410.9              1.2      337배
   100000         1819.5              2.8      647배

이 측정 예시에서는 정렬 시간을 포함해도 약 647배 빨랐다. 절대 시간과 배율은 실행 환경에 따라 달라진다. 정렬은 비용이 아니라 투자라는 것이 PART 2 전체의 관점이고, 12장 이분 탐색·14장 투 포인터가 모두 “정렬되어 있다”를 전제로 한다.

1.3 그런데 공짜는 아니다

qsort는 비교 함수를 넘겨받아 동작한다. 그 함수가 지켜야 할 규약이 있고, 어기면 틀린 답이 조용히 나온다. 이 장의 절반은 그 규약 이야기다.

함정 ①

return a - b; — 가장 흔하고, 큰 수에서 정렬이 깨진다 (4.1절)

함정 ②

return a > b; — 지금 환경에서는 되는 것처럼 보이지만 쓰면 안 된다 (4.2절)

2개념

2.1 qsort의 네 인자

#include <stdlib.h>

void qsort(void *base,          /* ① 정렬할 배열의 시작 주소 */
           size_t nmemb,        /* ② 원소의 개수 (바이트 아님) */
           size_t size,         /* ③ 원소 하나의 크기 */
           int (*cmp)(const void *, const void *));   /* ④ 비교 함수 */

/* 쓰는 모양 */
qsort(a, n, sizeof(int), cmp_asc);

왜 void *인가 — 외우지 말고 이해한다

qsort는 무엇을 정렬하는지 모른다. 그래서 타입을 숨긴 void *로 받고, 원소 크기(③)만 알면 자리를 바꿀 수 있다. 순서를 정하는 일만 우리에게 맡긴다(④).

가장 흔한 두 가지 실수

  • ②에 바이트 수를 넣는다 — qsort(a, n*sizeof(int), ...)는 배열 밖을 건드린다
  • ③에 배열 전체 크기를 넣는다 — sizeof(a)가 아니라 sizeof(a[0])이다

2.2 비교 함수의 규약

비교 함수는 두 원소를 받아 셋 중 하나를 돌려준다. 정확한 값이 아니라 부호만 본다.

돌려줄 값뜻결과
음수 (예: −1)a가 b보다 앞a가 먼저 놓인다
0비교 기준이 동률어느 쪽이 앞인지 정하지 않는다
양수 (예: 1)a가 b보다 뒤b가 먼저 놓인다

이 교재의 표준 작성법

static int cmp_asc(const void *x, const void *y){
    int a = *(const int *)x, b = *(const int *)y;
    return (a > b) - (a < b);        /* -1, 0, 1 중 하나 */
}

(a > b)와 (a < b)는 각각 0 또는 1이므로, 그 차는 −1 · 0 · 1이 된다. 뺄셈을 쓰지 않으므로 넘침이 없고, 세 상태를 모두 표현한다. 외워 둘 만한 한 줄이다.

Q. if문으로 써도 되나요?
된다. if (a < b) return -1; if (a > b) return 1; return 0;도 완전히 같다. 셋을 다 돌려주기만 하면 형태는 자유다. 다만 다중 키(2.3절)에서는 한 줄짜리가 훨씬 읽기 좋다.

2개념 (이어서)

2.3 다중 키 — “같으면 다음 기준으로”

“점수 내림차순, 점수가 같으면 이름 오름차순”처럼 기준이 여럿인 정렬은 비교 함수 하나로 표현한다. 아래의 Rec 자료형은 3.1절에 정의되어 있으며, strcmp를 쓰려면 <string.h>가 필요하다. 이름 문자열은 반드시 널 문자로 끝나야 한다.

규칙

첫 기준으로 비교해서 승부가 나면 바로 돌려주고, 0이면(같으면) 다음 기준으로 내려간다.

static int cmp_multi(const void *x, const void *y){
    const Rec *a = x, *b = y;
    if (a->score != b->score)
        return (a->score < b->score) - (a->score > b->score);  /* 점수 내림차순 */
    return strcmp(a->name, b->name);                            /* 같으면 이름 오름차순 */
}

내림차순은 부등호를 뒤집는다

오름차순이 (a > b) - (a < b)라면 내림차순은 (a < b) - (a > b)다. 두 항의 자리만 바꾸면 된다. 헷갈리면 “작은 것이 뒤로 가야 하니 작을 때 양수”로 외운다. -cmp_asc(x,y)는 이 교재의 cmp_asc가 −1·0·1만 반환하므로 안전하다. 다만 일반적인 비교 함수는 INT_MIN까지 반환할 수 있어 무조건 부호를 뒤집으면 오버플로가 날 수 있다. 여기서는 부등호를 직접 뒤집는 작성법을 권장한다.

2.4 안정성은 보장되지 않는다

안정 정렬(stable sort)이란 값이 같은 원소들의 원래 순서가 그대로 유지되는 정렬이다. 표준은 qsort가 안정적이라고 보장하지 않는다.

둘 다 틀린 정렬이 아니다. 비교 함수가 “점수가 같으면 0”이라고 했으므로, 그 셋의 순서는 정해 주지 않은 것이다. 문제가 “점수가 같으면 입력 순서대로”를 요구한다면, 그것을 비교 함수에 적어야 한다(3.3절).

3구현

3.1 cmp 3종 — 필수 구현

/* ① 정수 오름차순 */
static int cmp_asc(const void *x, const void *y){
    int a = *(const int *)x, b = *(const int *)y;
    return (a > b) - (a < b);
}
/* ② 정수 내림차순 — 두 항의 자리만 바꾼다 */
static int cmp_desc(const void *x, const void *y){
    int a = *(const int *)x, b = *(const int *)y;
    return (a < b) - (a > b);
}
/* ③ 구조체 다중 키 : 점수 내림차순, 같으면 이름 오름차순 */
typedef struct { int score; char name[16]; int idx; } Rec;

static int cmp_multi(const void *x, const void *y){
    const Rec *a = x, *b = y;
    if (a->score != b->score) return (a->score < b->score) - (a->score > b->score);
    return strcmp(a->name, b->name);
}

const void *를 받아 바로 쓰는 두 가지 방법

정수는 *(const int *)x로 값을 꺼내고, 구조체는 const Rec *a = x;처럼 포인터째로 받는다. 구조체를 통째로 복사하지 않으므로 더 빠르고, a->score처럼 쓸 수 있어 읽기도 좋다. C에서는 void *를 다른 포인터에 그냥 대입할 수 있어 형 변환을 적지 않아도 된다.

3.2 구조체 정렬의 모양

static Rec r[MAXN];
int n;
...
qsort(r, (size_t)n, sizeof(Rec), cmp_multi);      /* sizeof(r) 이 아니다 */

for (int i = 0; i < n; i++)
    printf("%s %d\n", r[i].name, r[i].score);
Q. 구조체 대신 배열 여러 개(score[], name[])를 쓰면 안 되나요?
별개의 여러 배열을 qsort 한 번으로 함께 재배열할 수는 없다. 한쪽 배열만 정렬하면 다른 배열과 짝이 어긋나기 때문이다. 함께 움직여야 하는 값들은 하나의 구조체로 묶는다 — 구조체를 쓰는 중요한 이유 중 하나다. 굳이 배열을 유지하려면 인덱스 배열을 정렬하는 방법이 있다(도전 C1의 변형).

3.3 안정성 복구 — 인덱스를 끼워 넣는다

“점수가 같으면 입력 순서대로”가 필요하면, 입력 순서를 기록해 두고 마지막 기준으로 쓴다.

/* 함수는 main 바깥에 정의한다. Rec 정의는 3.1절 참조. */
static int cmp_stable(const void *x, const void *y){
    const Rec *a = x, *b = y;
    if (a->score != b->score) return (a->score > b->score) - (a->score < b->score);
    return (a->idx > b->idx) - (a->idx < b->idx);
}
/* main 내부: r 배열과 n을 준비한 뒤 */
for (int i = 0; i < n; i++) {
    scanf("%d", &r[i].score);  r[i].idx = i;
}
qsort(r, (size_t)n, sizeof(r[0]), cmp_stable);

이 방법이 가진 장점

idx는 서로 다른 입력 원소마다 고유한 값이므로, 서로 다른 두 원소를 비교할 때는 두 번째 기준까지 가면 동률이 생기지 않는다. (같은 원소를 자기 자신과 비교하면 0이다.) 그 결과 서로 다른 원소의 순서가 완전히 정해지므로 구현이 무엇이든 결과가 똑같다. “안정적인지 아닌지”를 걱정할 필요 자체가 사라진다.

3.4 실측 — 안정성을 정말 믿어도 되는가

2.4절에서 “보장되지 않는다”고 했다. 그렇다면 실제로는 어떤가. 직접 재 보았다.

$ ./stable2      점수는 10종류뿐인 입력, '입력 순서가 뒤바뀐 이웃'의 수
        n          표준 qsort        직접 짠 퀵소트

정직하게 — 이 환경의 qsort는 안정적이었다

10만 개를 정렬해도 뒤바뀐 쌍이 하나도 없었다. 이 실행 환경에서는 결과적으로 입력 순서가 유지되었지만, 실측 결과만으로 내부 정렬 알고리즘이나 다른 환경의 동작을 단정할 수는 없다.

그런데 그것은 약속이 아니다. 같은 비교 함수를 퀵소트에 넘기면 10만 개 중 4만 9천 쌍이 뒤집힌다. C 라이브러리 구현이나 버전이 바뀌면 qsort에서 동점 원소의 순서가 달라질 수 있다. “내 컴퓨터에서는 되던데”가 통하지 않는 전형적인 자리다.

작은 예 (점수, 입력순서)
  입력        : 90(0) 70(1) 90(2) 70(3) 90(4) 80(5) 70(6) 80(7)
  직접 퀵소트 : 70(3) 70(6) 70(1) 80(5) 80(7) 90(0) 90(2) 90(4)   ← 70들이 3,6,1
  표준 qsort  : 70(1) 70(3) 70(6) 80(5) 80(7) 90(0) 90(2) 90(4)   ← 우연히 유지

그래서 결론은 하나다

문제가 “같으면 입력 순서대로”를 요구하면, 되는지 시험해 보지 말고 3.3절처럼 idx를 끼워 넣는다. 비용은 int 하나(4바이트)와 비교 한 줄이다. 그 값으로 “환경이 달라져도 같은 답”을 산다.

3.5 속도 — qsort는 얼마나 느린가

qsort는 비교할 때마다 전달된 비교 함수를 호출한다. 전용 정렬보다 느릴 수 있지만, 속도 차이는 구현과 환경에 따라 달라진다. 한 실행 예시를 보자.

        n      qsort(ms)   전용 병합 정렬(ms)      배수    답 일치
   200000           25.1              20.0      1.3배        O
  1000000          144.7             121.2      1.2배        O
  2000000          323.2             240.7      1.3배        O

이 측정에서는 약 1.2~1.3배였지만, 이는 보편적인 속도 차이가 아니다. 비교 함수 비용, 입력 데이터, 라이브러리 구현에 따라 오히려 다른 결과가 나올 수도 있다. 정렬 구현이 문제의 핵심이 아니라면 표준 qsort부터 사용하는 편이 실수를 줄인다.

4함정과 복잡도

4.1 함정 ① — return a - b;

교과서와 인터넷에서 자주 보이는 형태다. 두 정수의 차가 int 범위를 벗어나면 부호 있는 정수 오버플로(정의되지 않은 동작)가 발생해 비교 결과를 믿을 수 없다.

정수 비교 규약 확인
입력          2000000000 -2000000000    7   -7  1500000000 -1500000000
안전한 비교   -2000000000 -1500000000   -7    7  1500000000  2000000000

(-2000000000) - (2000000000)의 수학적 결과 = -4000000000
int 형에서 이 뺄셈은 범위 초과 → C 언어의 정의되지 않은 동작!
※ 일부 환경에서 294967296처럼 보일 수 있으나 C는 이를 보장하지 않는다.

왜 결과를 예측할 수 없는가

int가 보통 담는 범위는 −2,147,483,648부터 2,147,483,647까지다. −40억은 범위 밖이다. C의 부호 있는 정수 오버플로는 단순한 순환 계산으로 정의되지 않는다. 정렬이 틀릴 수도 있고, 컴파일 최적화에 따라 다른 현상이 생길 수도 있다. 안전한 차를 구하려면 (long long)a - b처럼 먼저 넓은 형으로 변환해야 한다.

언제 안전한가 — 알고는 있어야 한다

두 값이 모두 0 이상이고 10억 이하처럼 차가 범위를 넘지 않는 것이 확실하면 a - b도 틀리지 않는다. 그래서 많은 코드가 멀쩡히 돌아간다. 하지만 “이 문제의 값 범위가 얼마였더라”를 매번 확인하느니 (a>b)-(a<b)를 외우는 편이 싸다.

4함정과 복잡도 (이어서)

4.2 함정 ② — return a > b;

0 또는 1만 돌려주는 방식은 두 원소의 대소 관계를 올바르게 표현하지 못한다. C의 qsort 비교 함수는 작은 값이 앞서야 할 때 음수, 동률이면 0, 뒤서야 할 때 양수를 반환해야 한다.

두 방향을 모두 비교해 보면
cmp(2,5) = (2 > 5) = 0    /* 작지만 동률이라고 보고 */
cmp(5,2) = (5 > 2) = 1    /* 반대 방향은 크다고 본다 */
올바른 비교: cmp(2,5) = -1, cmp(5,2) = +1

문제의 핵심은 반대칭성과 동률 구별

값이 다르면 비교 방향을 뒤집었을 때 반환값의 부호도 반대여야 한다. 그런데 return a > b;는 작다와 같다를 모두 0으로 처리한다. 따라서 비교 규약을 위반한다. 어떤 환경에서 정렬된 듯한 결과가 나와도 올바름이나 재현성을 보장하지 않는다.

실험 결과는 정답의 근거가 아니다

잘못된 비교 함수를 qsort에 주고 정렬에 성공한 횟수를 세는 실험은 가능하지만, 성공 횟수나 실패 형태는 표준이 정해 주지 않는다. 같은 코드라도 구현에 따라 결과가 달라진다. 다중 키 정렬에서도 첫 기준의 동률 여부를 판단할 수 없으므로 (a > b) - (a < b)처럼 세 상태를 모두 반환해야 한다.

4.3 비교 함수가 지켜야 할 세 가지

성질뜻어기면
반대칭성cmp(a,b)가 음수면 cmp(b,a)는 양수원소 순서에 따라 결과가 달라진다
추이성a<b 이고 b<c 이면 a<c정렬 자체가 말이 되지 않는다 (도전 C2)
일관성같은 두 값에 대해 언제나 같은 답호출할 때마다 결과가 바뀐다

추가로 같은 원소를 자신과 비교하면 0이어야 한다. 세 가지 성질은 바르게 작성한 숫자·문자열 비교에서 자연스럽게 만족한다. 문제는 “가위바위보” 같은 순환 관계나, 난수·시간을 섞은 비교 함수를 만들 때다 — 도전 C2에서 직접 만들어 본다.

4.4 복잡도

항목복잡도비고
qsort 전체구현에 따라 다름C 표준은 시간복잡도를 보장하지 않는다. 일반적인 구현의 평균은 O(N log N) 수준
비교 함수 호출 횟수구현·입력에 따라 다름O(N log N) 정렬에서는 대체로 그 규모지만, 정확히 N log₂N번은 아니다.
추가 메모리구현에 따라 다름병합 계열이면 O(N)을 더 쓴다. 메모리가 빠듯하면 확인할 것
정렬 후 중복 검사O(N log N)이중 루프 O(N²) 대비 647배 (1.2절)

N log N을 수로 바꿔 본다 — 02장의 습관

예제 1 비교 함수 읽기

다음 네 비교 함수를 qsort에 넘기면 각각 어떤 순서가 되는가? 문제가 있으면 지적하라. (값은 모두 0 이상 10억 이하)

/* 가 */ return (a > b) - (a < b);
/* 나 */ return (a < b) - (a > b);
/* 다 */ return b - a;
/* 라 */ return a % 10 - b % 10;
구분결과 순서판정
가오름차순표준 형태. 문제 없음
나내림차순두 항의 자리만 바꿨다. 문제 없음
다내림차순값이 0~10억이므로 이번에는 안전하다. 음수가 섞이면 깨진다
라일의 자리 오름차순규약 위반은 아니다. 다만 일의 자리가 같으면 0을 돌려주므로 그들 사이 순서는 정해지지 않는다

라가 중요하다. 일의 자리로만 비교하는 것은 잘못이 아니라 선택이다. 다만 “일의 자리가 같으면 원래 순서대로”를 원한다면 idx를 덧붙여야 한다(3.3절). 비교 함수가 0을 돌려주는 자리는 전부 “정하지 않았다”는 선언이다.

예제 2 다중 키 설계

학생 기록을 ① 학년 오름차순 ② 같으면 점수 내림차순 ③ 같으면 이름 사전순으로 정렬하는 비교 함수를 쓰라. Rec = { int grade, score; char name[16]; }

static int cmp3(const void *x, const void *y){
    const Rec *a = x, *b = y;
    if (a->grade != b->grade) return (a->grade > b->grade) - (a->grade < b->grade);
    if (a->score != b->score) return (a->score < b->score) - (a->score > b->score);
    return strcmp(a->name, b->name);
}
  • 오름차순은 (a>b)-(a<b), 내림차순은 (a<b)-(a>b) — 한 함수 안에 섞여 있어도 각 줄만 보면 된다
  • strcmp는 이미 음수·0·양수를 돌려주므로 그대로 쓴다. 사전 역순이 필요하면 strcmp(b->name, a->name)
  • 마지막 기준이 중복될 수 있으면(동명이인) 그 뒤에 idx를 하나 더 붙인다

6연습 문제

01~05는 공책에, 06~10은 컴퓨터로 푼다. 제한 시간 60분. 이 장의 코드는 짧다. 대신 “왜 그렇게 쓰는가”를 답할 수 있어야 한다.

01qsort의 네 인자를 각각 쓰고, 왜 void *와 원소 크기를 함께 받아야 하는지 두 줄로 설명하라.
02비교 함수가 돌려주는 세 가지 값의 뜻을 쓰라. 그리고 (a > b) - (a < b)가 왜 −1·0·1을 만드는지 a<b, a==b, a>b 세 경우로 나누어 확인하라.
03다음 비교 함수들이 만드는 순서를 각각 쓰고, 문제가 있으면 지적하라. (값의 범위는 −20억 ~ +20억, C의 %는 음수에 대해 음수 나머지가 나올 수 있다)
① return a - b;   ② return (a < b) - (a > b);   ③ return 0;   ④ return (a % 3) - (b % 3);
04Rec = { int w, h; int idx; }를 ① 넓이(w×h) 내림차순 ② 같으면 w 오름차순 ③ 같으면 입력 순서로 정렬하는 비교 함수를 쓰라. 0 ≤ w, h ≤ 100,000이므로 넓이는 최대 10,000,000,000이다. long long으로 형 변환한 다음 곱할 것.
05“점수가 같으면 입력 순서대로”가 필요한 문제에서, 인덱스를 끼워 넣는 방법과 qsort가 안정적이기를 기대하는 방법을 비교하라. 후자가 왜 위험한지 3.4절의 숫자를 들어 쓸 것.
06cmp 3종(정수 오름·내림, 구조체 다중 키)을 구현하라. 각각에 대해 정렬 결과가 실제로 정렬되어 있는지 검사하는 함수를 만들어 함께 돌릴 것.
07a - b 방식과 (a>b)-(a<b) 방식을 둘 다 만들어, 20억 근처의 값이 섞인 배열에서 결과를 비교하라. 안전한 비교 방식 (a>b)-(a<b)와 (long long)a-b의 부호를 이용하는 방식을 직접 구현해 20억 근처의 값이 섞인 배열에서 비교하라. int형 a-b가 왜 위험한지는 설명으로 증명하고, 실행하지 않는다. (long long)(-2000000000) - 2000000000LL을 출력해 올바른 차를 확인하라.
08a > b 방식을 ① 표준 qsort와 ② 직접 짠 퀵소트에 각각 넘겨 결과를 비교하라. n = 10 / 100 / 1000에서 각 100번씩 돌려 실패 횟수를 세어 보라. 단, 실패 횟수 및 두 구현의 차이는 보장되지 않으며, 반드시 cmp(a,b)와 cmp(b,a)의 부호를 검사해 규약 위반을 증명하라.
09점수가 10종류뿐인 입력 10만 개를 만들어, 점수만 비교하는 함수로 ① 표준 qsort와 ② 직접 짠 퀵소트로 각각 정렬하라. 입력 순서가 뒤바뀐 이웃의 수를 세어 비교하고, 결론을 한 줄로 쓰라.
10“이 수열에 같은 값이 있는가”를 ① 이중 루프와 ② 정렬 후 인접 비교로 구현해 n = 20,000 / 50,000 / 100,000에서 시간을 비교하라. 중복이 없는 입력을 써야 하는 이유를 함께 쓸 것.

C1구간이 겹치는가
N개의 구간 [l, r)이 주어진다. 서로 겹치는 두 구간이 하나라도 있는가? N ≤ 500,000, 0 ≤ l < r ≤ 10억이다(빈 구간은 주어지지 않는다).
예 : [0,10) [20,30) [5,7) → 겹친다 ([0,10)과 [5,7))
(1) 모든 쌍을 보는 풀이의 복잡도는? N = 100,000에서 몇 초가 걸릴지 어림하라.
(2) 시작점 기준으로 정렬하면 어떤 일이 가능해지는가? 비교 함수를 쓰라.
(3) 정렬한 뒤 한 번만 훑어서 판정하는 방법을 설계하라. 힌트 — 지금까지 본 구간들의 “가장 오른쪽 끝”만 기억하면 된다.
(4) (3)이 올바른 이유를 설명하라. “바로 앞 구간과만 비교하면 되지 않나?”라는 반론에 답할 것.
(5) 구현해서 (1)과 시간을 비교하라. 겹치지 않는 입력이 왜 최악인지도 쓸 것.
C2규약을 어긴 비교 함수
0 = 바위, 1 = 보, 2 = 가위라고 하자. “이기는 쪽이 앞”으로 정렬하고 싶어 이런 비교 함수를 썼다.
if (a == b) return 0; if ((a+1)%3 == b) return -1; return 1;
(1) 이 함수에 따르면 0 < 1, 1 < 2, 2 < 0 이다. 어떤 성질을 어겼는가? (4.3절)
(2) {0,1,2,0,1,2,0,1,2}를 이 함수로 qsort하면 결과가 어떻게 나오는가? 직접 돌려 적으라.
(3) 출력 결과가 어떻든 모든 i < j 쌍에 대해 앞 원소가 뒤 원소보다 뒤서지 않는지 검사하라. 이웃끼리만 검사해서는 충분하지 않은 이유를 0 < 1 < 2 < 0 순환에서 찾아 설명하라. 출력 순서는 환경에 따라 달라질 수 있다.
(4) 이런 “순환하는 우열 관계”를 정렬로 표현할 수 없는 이유를 설명하라.
(5) 그렇다면 가위바위보 승부를 자료구조로는 어떻게 다루어야 하는가? 한 줄로 제안하라.

두 문항이 겨냥하는 것

C1은 이 장의 주제를 직접 묻는다 — 정렬 자체가 답이 아니라, 정렬해 두었기 때문에 한 번 훑기가 가능해진다. (4)의 반론이 핵심이고, 같은 기법이 14장 투 포인터와 19장 회의실 배정으로 이어진다.

흔한 생각무엇이 틀렸나바로잡기
“return a - b;가 간단하다”큰 수에서 넘쳐 조용히 깨진다(a>b)-(a<b)를 외운다 (4.1절)
“a > b도 되던데요”비교 규약을 어기며 작다·같다를 구분 못 한다“작다”와 “같다”를 구분 못 한다 (4.2절)
“qsort는 안정적이다”표준이 보장하지 않는다. 구현이 바뀌면 깨진다필요하면 idx를 끼워 넣는다 (3.3절)
“sizeof(a)를 넘기면 된다”배열 전체 크기다. 원소 하나의 크기여야 한다sizeof(a[0])으로 쓰는 습관
“두 번째 인자는 바이트 수”원소 개수다qsort(a, n, sizeof(a[0]), cmp)
“내림차순은 -cmp(x,y)”반환값이 INT_MIN이면 부호를 못 뒤집는다부등호를 직접 뒤집는다 — (a<b)-(a>b)
“구조체 말고 배열 여러 개로”한쪽만 정렬되어 짝이 어긋난다함께 움직일 값은 구조체로 묶는다 (3.2절)
“직접 짜면 더 빠르다”비교 대상·환경에 따라 성능이 달라진다그 시간에 문제를 생각한다 (3.5절)

자가 점검

  • qsort 네 인자를 보지 않고 쓸 수 있다
  • 오름·내림·다중 키 비교 함수를 백지에서 쓸 수 있다
  • a - b가 깨지는 값을 직접 만들 수 있다
  • a > b를 쓰면 안 되는 이유를 환경과 무관하게 설명할 수 있다
  • 안정성이 필요한지 판단하고, 필요하면 idx를 넣을 수 있다
  • “정렬해 두면 가능해지는 것”을 세 가지 들 수 있다
