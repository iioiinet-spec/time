1왜 필요한가

11장에서 정렬하고, 12장에서 찾고, 13장에서 답을 좁혔다. 이 장은 포인터 두 개로 한 번만 훑어 구간 문제를 푼다. 이미 두 번 예고된 기법이다 — 08장 도전 C2와 12장 도전 C1이 모두 여기로 모인다.

1.1 이중 루프처럼 보이는 것을 한 번에

합이 S 이상인 최단 구간

0 이상의 정수 수열 A와 양의 정수 S가 주어진다. 합이 S 이상인 가장 짧은 연속 구간의 길이는? (N ≤ 1,000,000)

모든 구간을 보면 O(N²)이다. 그런데 값이 전부 0 이상이고 S > 0이라면 포인터 두 개로 한 번만 훑으면 된다 — 08장 C2에서 논증을 보았고, 여기서 제대로 만든다.

1.2 12장에서 푼 문제를 다시 — 이번엔 O(N)

12장 도전 C1에서 합이 S인 두 수를 “정렬 + 각 원소마다 이분 탐색”으로 풀었다. O(N log N)이다. 투 포인터로 하면 정렬 뒤 한 번만 훑으면 된다. 정렬 비용까지 포함하면 여전히 O(N log N)이며, 정렬된 입력을 받았다면 O(N)이다.

1.3 공짜는 아니다 — 전제가 있다

08장 C2 (5)에서 이미 보았다. 값이 모두 0 이상이고 S > 0이라는 조건이 깨지면 투 포인터는 틀린 답을 낸다.

A = 5  -10  20,  S = 15   →   투포인터 3,  정답 1

음수 포함 입력에서는 정답과 다른 결과가 나올 수 있음 — 불일치 발생
   (n = 1~10, 값 −10~10, S = 1~15; 정의된 범위 안에서 비교)
0 이상만 포함하는 입력(S > 0)에서는 완전 탐색과 일치하도록 검증한다

오류율은 입력 분포와 S의 범위에 따라 달라진다. 과거 측정값 하나를 보편적인 정확도로 받아들이면 안 된다(연습 10) — “몇 %가 틀리는가”는 알고리즘의 성질이 아니라 시험 방법의 성질이다. 11·12·13장에서 반복해 만난 숫자의 모양이다 — “테스트를 통과했다”가 “맞다”가 아닌 바로 그 구간이다. 전제를 말로 확인하는 것이 이 장의 절반이다(4.2절).

2개념

2.1 두 포인터, 한 방향

O(N)인 이유 — 08장 4.1절과 같은 논증

while이 for 안에 있어 이중 루프처럼 보이지만, 슬라이딩 윈도우의 lo와 hi는 각각 0에서 N까지 오른쪽으로만 간다. 되돌아가는 일이 없으므로 두 포인터의 전진 횟수를 합쳐도 2N 이하다. 05·06·07·08장에서 네 번, 09장 C2에서 한 번 쓴 그 논증이다.

2.2 불변식 — 무엇을 지키며 움직이는가

투 포인터를 쓸 때 가장 먼저 정할 것은 “구간이 언제나 만족하고 있어야 하는 성질”이다. 그것을 불변식이라 하고, 포인터를 움직이는 규칙은 불변식이 정한다.

문제불변식깨지면
합 ≥ S 최단 구간합이 S 이상이면 왼쪽을 더 빼면 S 미만이 될 때까지 줄인다lo를 전진
중복 없는 최장 구간구간에 같은 값이 두 번 없다lo를 전진
최댓값−최솟값 ≤ K구간의 최댓값−최솟값 ≤ Klo를 전진

셋 다 모양이 같다

for (int hi = 0; hi < n; hi++) {
    /* ① hi 를 구간에 넣는다 */
    while (/* 불변식이 깨졌다 */) {
        /* ② lo 를 빼며 전진시킨다 */
    }
    /* ③ 지금 구간으로 답을 갱신한다 */
}

①②③의 순서가 고정이다. ②를 ①보다 먼저 하면 아직 넣지도 않은 원소로 판단하게 되고, ③을 ② 앞에 두면 불변식이 깨진 구간으로 답을 갱신한다.

Q. 슬라이딩 윈도우에서도 “버린다”는 말을 쓰나요?
쓴다. lo를 전진시키는 것은 “이 원소를 포함하는 구간은 더 볼 필요가 없다”는 선언이다. 합 ≥ S 문제에서 lo를 한 칸 옮겼다는 것은 “lo에서 시작하는 구간 중 가장 짧은 것은 이미 봤다”는 뜻이다. 한 번 버린 것은 다시 보지 않는다 — 그래서 O(N)이 된다.

슬라이딩 윈도우둘 다 왼쪽 → 오른쪽구간(연속)에 대한 문제. 최단·최장 구간, 합·개수 조건

가운데에서 만난다		정렬된 수열에서 두 원소를 고르는 문제. 합이 S인 쌍

마주 보는 쪽이 왜 옳은가

a[lo] + a[hi] < S라면 hi보다 작은 어떤 것과 짝지어도 합은 더 작다. 그러므로 a[lo]는 어떤 짝과도 S를 만들 수 없고, 버려도 된다 — 08장 2.4절의 지배 관계와 정확히 같은 논법이다. 반대로 합이 크면 a[hi]를 버린다.
정렬되어 있지 않으면 이 논법이 통하지 않는다. 그래서 11장이 먼저 와야 했다.

2.4 길이가 고정된 윈도우 — 가장 쉬운 경우

구간의 길이 K가 미리 정해져 있으면 lo를 따로 둘 필요도 없다. 한 칸 밀 때 들어오는 것 하나, 나가는 것 하나만 반영한다.

/* 길이 K 구간의 최대 합: 1 <= K <= n */
long long s = 0;
for (int i = 0; i < K; i++) s += a[i];       /* 첫 창을 만든다 */
long long best = s;
for (int hi = K; hi < n; hi++) {
    s += (long long)a[hi];                     /* 먼저 넓은 형으로 변환 */
    s -= (long long)a[hi - K];
    if (s > best) best = s;
}

고정 길이는 음수가 있어도 괜찮다

1.3절에서 보았듯 음수가 섞이면 가변 길이 윈도우는 오답을 낼 수 있다. 그런데 고정 길이는 음수를 섞어도 원본 무작위 대조에서 불일치가 0/15,600이다. 차이는 “포인터를 움직일지 판단하는 일”이 있느냐다 — 고정 길이는 판단 없이 무조건 한 칸씩 밀기만 하므로 합의 증감을 믿을 필요가 없다. 양수 전제는 필요 없지만, 1 ≤ K ≤ N과 합계 자료형은 확인해야 한다.

3구현

3.1 합이 S 이상인 최단 구간

/* 전제: n >= 0, a[i] >= 0, S > 0. 빈 구간은 허용하지 않음 */
static int shortest_ge(const int *a, int n, long long S){
    if (S <= 0) return n > 0 ? 1 : 0;  /* 0 이상 수열의 비어 있지 않은 최소 길이 */
    long long sum = 0;
    int lo = 0, best = n + 1;
    for (int hi = 0; hi < n; hi++) {
        sum += a[hi];                                  /* ① 넣는다 */
        while (lo <= hi && sum - a[lo] >= S) sum -= a[lo++];       /* ② 줄여도 되는 만큼 줄인다 */
        if (sum >= S && hi - lo + 1 < best)            /* ③ 답 갱신 */
            best = hi - lo + 1;
    }
    return best > n ? 0 : best;                        /* 없으면 0 */
}

while 조건이 sum >= S가 아니라 sum - a[lo] >= S인 이유

불변식을 “lo를 한 칸 더 빼면 S 미만이 되는 상태”로 잡았기 때문이다. 이렇게 하면 ③에서 지금 구간이 곧 “hi로 끝나는 가장 짧은 구간”이 되어 답 갱신이 한 줄로 끝난다.
sum >= S에서 답을 먼저 갱신하고 왼쪽을 빼는 방식도 옳다(08장 C2의 형태). 이 코드는 S > 0, 비음수 수열을 전제로 하며, S ≤ 0이면 길이 1을 따로 처리한다. 둘 다 맞지만 섞으면 틀린다 — 불변식을 먼저 정하고 거기에 맞춰 세 줄을 쓴다.

3.2 합이 S인 두 수 — 마주 보는 투 포인터

/* 비내림차순으로 정렬된 배열. 서로 다른 인덱스의 쌍(i < j)을 센다 */
static long long pairs(const int *a, int n, long long S){
    int lo = 0, hi = n - 1;
    long long c = 0;
    while (lo < hi) {
        long long s = (long long)a[lo] + a[hi];       /* 넘침 주의 */
        if      (s < S) lo++;
        else if (s > S) hi--;
        else {                                         /* 같은 값 묶음을 한 번에 센다 */
            if (a[lo] == a[hi]) {                      /* 양쪽이 같은 값 하나의 덩어리 */
                long long m = hi - lo + 1;
                c += m * (m - 1) / 2;  break;
            }
            int cl = 1, ch = 1;
            while (lo+1 < hi && a[lo+1] == a[lo]) { lo++; cl++; }
            while (hi-1 > lo && a[hi-1] == a[hi]) { hi--; ch++; }
            c += (long long)cl * ch;
            lo++; hi--;
        }
    }
    return c;
}

중복 처리가 이 코드의 전부다

합이 맞았을 때 lo++; hi--;만 하면 같은 값이 여러 개일 때 쌍을 빠뜨린다. 왼쪽에 같은 값이 cl개, 오른쪽에 ch개면 쌍은 cl × ch개다.
양쪽이 같은 값일 때(예: S=10, 값이 전부 5)는 한 덩어리 안에서 둘을 고르는 것이므로 m(m−1)/2다 — 이 경우를 빠뜨리면 두 배로 센다.

3.3 중복 없는 최장 구간 — 윈도우 카운트 배열

구간 안에 같은 값이 두 번 들어오지 않도록 유지한다. 값마다 몇 개 들어 있는지를 배열로 센다.

#include <string.h>  /* memset */
#define MAXV 100001       /* 예시: 값이 0..100000 */
static int cnt[MAXV];                /* 반드시 0 <= a[i] < MAXV */

static int longest_distinct(const int *a, int n){
    memset(cnt, 0, sizeof cnt);
    int lo = 0, best = 0;
    for (int hi = 0; hi < n; hi++) {
        cnt[a[hi]]++;                                  /* ① */
        while (cnt[a[hi]] > 1) cnt[a[lo++]]--;         /* ② 방금 넣은 값이 2개면 줄인다 */
        if (hi - lo + 1 > best) best = hi - lo + 1;    /* ③ */
    }
    return best;
}

while 조건이 cnt[a[hi]] > 1인 것이 핵심

“구간에 중복이 있는가”를 전부 확인할 필요가 없다. 중복이 생겼다면 반드시 방금 넣은 a[hi] 때문이기 때문이다(그 전까지는 불변식이 지켜지고 있었다). 불변식을 쓰면 검사가 한 값으로 줄어든다 — 이것이 불변식을 먼저 정하는 이유다.

값의 범위가 크면 배열을 쓸 수 없다

값이 음수이거나 MAXV 이상이면 위 배열 코드에 그대로 접근해서는 안 된다. 값이 10억까지라면 큰 cnt 배열은 비효율적이다. 그때는 값을 0…M−1(M ≤ N)로 바꿔(좌표 압축) 쓰거나 21장 해시 테이블을 쓴다. 좌표 압축은 11장 정렬 + 12장 lower_bound로 만든다(사전 처리 O(N log N)). 또한 memset(cnt, 0, sizeof cnt)에는 O(MAXV)가 걸리므로 위 코드의 1회 전체 비용은 O(N + MAXV)이다.

3.4 실측

중복 없는 최장 구간 (n = 50,000), 값 종류를 바꿔 가며
     값 종류   최장 구간   투포(ms)   완전탐색(ms)     배수
         100          39       0.24            0.8        3배
        1000         147       0.38            2.7        7배
       50000         839       0.09           15.2      169배

왜 값 종류가 많을수록 차이가 커지는가

완전 탐색은 중복을 만나면 멈춘다. 값 종류가 적으면 몇 칸 만에 중복이 나와 금방 끝난다(100종류인 실험에서 최장 39칸). 값 종류가 많으면 구간이 길어져 안쪽 루프가 오래 돈다 — 그래서 169배가 된다.
최악 입력은 “값이 전부 다른” 경우이고 그때 완전 탐색은 O(N²)이다. 08~13장에서 반복한 대로, 무작위로 재면 기법의 가치를 과소평가한다.

왜 음수가 위험한가 — 한 문장으로

lo를 전진시키는 것은 “구간을 줄이면 합이 준다”는 믿음 위에 서 있다. 음수가 있으면 줄였는데 합이 늘 수 있고, 그러면 “더 줄여 볼 필요 없다”는 판단이 틀린다.
반례 A = [5, −10, 20], S = 15. 투 포인터는 3을 답하지만 정답은 1([20])이다. −10을 버리면 합이 늘어나는데 그 가능성을 보지 않는다. 08장 도전 C2 (5)에서 이미 만난 반례다.

Q. 음수가 있으면 이 문제는 어떻게 푸나요?
누적합 + 단조 덱으로 해결할 수 있다. P[i] = a[0]+…+a[i−1]로 두면 구간 [i,j)의 합은 P[j] − P[i]이다. 각 j에서 i < j이고 P[i] ≤ P[j] − S인 가장 큰 i를 찾아 구간 길이를 줄여야 한다. 접두합은 음수가 있으면 정렬되어 있지 않으므로 단순 lower_bound는 쓸 수 없다. 08장의 단조 덱으로 O(N)에 푼다 — 도전 C2에서 설계한다.

C2음수가 있어도 되는 최단 구간
1.3절에서 보았듯 음수가 섞이면 양수용 투 포인터가 오답을 낼 수 있다. 음수가 있어도 옳은 풀이를 설계하라. 수열 A(음수 포함)와 S가 주어질 때 합이 S 이상인 최단 구간의 길이를 구한다. N ≤ 200,000.

(2) 각 j에 대해 가장 큰 i (0 ≤ i < j)를 찾아야 한다. P[i]가 만족할 조건을 부등식으로 쓰라.

(4) 전체 복잡도를 O(N)으로 증명하고, 비음수 전용 투 포인터와 비교하라. 두 방식의 불변식은 어떻게 다른가?

도전 C2 정답 설계의 핵심

접두합 P[0..N]과 인덱스 덱을 사용한다. j를 0부터 N까지 올리면서 ① P[j]-P[dq.front] ≥ S인 동안 앞 원소로 정답을 갱신하고 제거 ② P[j] ≤ P[dq.back]인 동안 뒤 원소 제거 ③ j 삽입. 각 인덱스는 한 번 들어가고 한 번 나가므로 O(N)이다. 앞 제거는 가능한 최단 길이를 확인하는 것이고, 뒤 제거는 나중에 등장한 더 작거나 같은 접두합이 앞 후보를 지배하기 때문이다.

두 문항이 겨냥하는 것

C1은 설계서가 명시한 “08장 덱과의 결합”이다. 투 포인터가 구간을 움직이고, 단조 덱이 그 구간의 최댓값·최솟값을 O(1)에 알려 준다. 두 기법이 각자 하던 일을 그대로 하면서 합쳐진다 — PART 1과 PART 2가 만나는 자리다.
C2는 전제가 깨졌을 때 무엇을 하는가를 묻는다. 투 포인터의 단조 합 가정을 버리고, 누적합 + 08장 단조 덱을 결합한다. (3)(4)가 핵심 — 음수가 있어도 O(N)으로 풀 수 있으며 정확한 후보 관리가 필요하다. 전제가 성립하면 싼 방법을 쓰는 것이 알고리즘 설계다.

  • 전제가 깨졌을 때 돌아갈 방법(누적합+단조 덱)을 안다

PART 2를 마치며 — 다음은 단원평가 T2

11장에서 정렬하고, 12장에서 찾고, 13장에서 답을 좁히고, 14장에서 한 번에 훑었다. 네 장이 하나의 사슬이다 — 14장 C2는 누적합과 08장의 단조 덱을 결합하고, 3.3절의 좌표 압축은 11·12장으로 만든다.

그리고 PART 2는 “맞는지 어떻게 아는가”를 네 가지 모양으로 가르쳤다 —
11장 실험으로 참을 증명할 수 없다 · 12장 작은 범위면 전수로 증명할 수 있다 · 13장 범위가 크면 다시 못 한다 · 14장 전제를 말로 확인하라.
다음 차시 단원평가 T2(11–14장)가 이 네 가지를 묻는다. 그 뒤 PART 3(15–20장)은 트리와 우선순위로, 선형 구조를 떠난다.
